# Архитектурные факторы
## Функциональные требования
### Работа с каталогом
FR-01: Система должна предоставлять покупателям возможность поиска товаров по ключевым словам в названии в каталоге товаров
FR-02: Система должна позволять покупателю фильтровать товары в каталоге по следующим параметрам: категория, цвет, размер, рейтинг отзывов, сезонность и ценовой диапазон, а также сбросить все фильтры
FR-03: Система должна рассчитывать и отображать персональные рекомендации на основе контентной фильтрации (векторное представление атрибутов товара и профиля пользователя), а в случае отсутствия истории (новый пользователь без истории заказов) система должна отображать товары с наилучшей оценкой (рейтингом)
FR-04: Пользователь должен иметь возможность добавить товар в список избранных товаров и удалить его оттуда
FR-05: Количество товаров в списке избранных товаров не должно превышать 1000
FR-06: Система должна позволять покупателю добавлять товары в корзину с возможностью редактирования количества товаров и просмотром итоговой суммы 
FR-07: Количество разных товаров в корзине не должно превышать 100
FR-08: Система должна запрашивать подтверждение действия при попытке очистить корзину полностью
FR-09: Система должна позволять продавцу сортировать список его товаров по следующим критериям: категория, название, цена
FR-10: Система должна предоставлять продавцам возможность поиска товара по ключевым словам в названии
FR-11: Продавец должен иметь возможность добавлять карточку товара через форму с обязательными полями, загружать фото или видео в карточку товара, список SKU товара из файла и возможность редактировать как поля карточки, так и количество товара через добавление/удаление позиции товара по их SKU
FR-12: Продавец должен иметь возможность удалить или архивировать(скрыть из каталога) товар
FR-13: Система должна автоматически архивировать товар, если его количество равно 0
FR-14: Система должна запрашивать подтверждение удаления/архивации товара
### Работа с заказами
FR-15: Система должна позволять пользователю смотреть список своих заказов, а также фильтровать список(историю) заказов по статусу и дате заказа 
FR-16: Система должна позволять вводить промокод при оформлении заказа и применять его на сумму собранной корзины товаров
FR-17: Система должна убирать из заказа товары, которые были в корзине, но не в наличии у продавца с пересчетом итоговой суммы 
FR-18: Покупатели должны иметь возможность оформлять заказ с выбором оплаты: картой онлайн или по СБП
FR-19: Система должна подгружать данные о адресе доставки и другие данные о пользователе для оформления заказа из его аккаунта
FR-20: Система должна вернуть товары в корзину, если платеж был отклонен
FR-21: Система должна поменять статус заказа и удалить заказанный товар из корзины, если платеж был одобрен
FR-22: Пользователь должен иметь возможность отменить заказ, если он в статусе “Оформлен” или “Собирается” 
FR-23: Система должна уведомлять пользователя при смене статуса его заказа через вкладку уведомлений в веб-сервисе 
FR-24: Система должна предоставлять продавцам возможность просмотра списка пришедших ему заказов, а также поиска заказа по номеру
FR-25: Система должна уведомлять продавца при появлении нового заказа для него через вкладку уведомлений в веб-сервисе 
FR-26: Система должна предоставлять продавцу возможность фильтровать список заказов по следующим параметрам: товар, статус
FR-27: Продавец должен иметь возможность менять статус заказа с “Оформлен” на “Собирается” и из “Собирается” в “Отправлен”
FR-28: Система должна предлагать возможные переходы статуса заказа в виде выпадающего списка, отображая лишь допустимые переходы. Система не должна предлагать в выпадающем списке статусы, в которые нельзя перейти из текущего статуса(например, из “Оформлен” в “Доставлен”)
FR-29: Система должна требовать заполнения поля трек-номера посылки при переходе заказа в статус “Отправлен”
FR-30: Продавец должен иметь возможность менять статусы сразу нескольким выбранным заказам, если они находятся в одинаковом статусе(мультиселект) 
FR-31: Система должна обеспечивать безопасную сделку через интеграцию с платежным сервисом(PSP) для автоматического разделения выручки между комиссией маркетплейса и выплатой продавцу после успешного выполнения заказа
FR-32: Система должна обеспечивать холдирование средств покупателей, не начисляя их сразу после отправки заказа продавцу, делая это через задержку в виде 7 дней после перехода заказа в статус “Доставлен”
### Работа с возвратами
FR-33: Пользователь должен иметь возможность оформить запрос на возврат товара, указав причину возврата и приложив ее доказательства(фото/видео)
FR-34: Пользователь должен иметь возможность посмотреть список своих возвратов с их статусами, а также изменить статус возврата на “Отправлен”, заполнив трек-номер посылки  
FR-35: Система должна позволять пользователь менять статус возврата лишь в случае, если возврат одобрен Администратором(статус возврата = “Одобрен”). Система должна отображать в выпадающем списке статусов возврата лишь те, на переход в которые есть права у пользователя
FR-36: Система должна предоставлять администратору возможность посмотреть список возвратов, а также фильтровать список по статусу и сортировать их по дате
FR-37: Администратор должен иметь возможность менять статусы возврата с “Оформлен” на “Одобрен”/”Отклонен” и “Отправлен” на “Возвращен”, а также добавлять комментарий о причине изменения статуса
FR-38: Система должна предлагать возможные переходы статуса возврата в виде выпадающего списка, отображая лишь допустимые переходы. Система не должна предлагать в выпадающем списке статусы, в которые нельзя перейти из текущего статуса(например, “Оформлен” в “Возвращен”)
FR-39: Система должна вернуть средства покупателю в течение 7 дней после перехода возврата в статус “Возвращен”
FR-40: Система должна уведомлять администратора при появлении нового возврата через вкладку уведомлений в веб-сервисе 
FR-41: Система должна уведомлять пользователя при изменении статуса возврата через вкладку уведомлений в веб-сервисе 

### Работа с отзывами
FR-42: Пользователь (включая неавторизованного пользователя) должен иметь возможность читать отзывы к открытой карточке товара
FR-43: Пользователь с любой ролью авторизованного пользователя должен иметь возможность добавлять свой отзыв с текстом, оценкой товара и возможностью прикрепить к своему отзыву фото/видео, если он когда-либо приобретал этот товар
FR-44: Система должна предоставлять пользователю возможность сортировать список отзывов открытой карточки товара по дате и оценке 
FR-45: Пользователь должен иметь возможность редактировать свой отзыв в течение часа после его публикации, а также удалить его без ограничения по времени
FR-46: Продавец должен иметь возможность ответить на отзыв к своему товару, а также удалить свой ответ на отзыв покупателя без ограничения по времени
FR-47: Система должна запрашивать у пользователя подтверждение удаления отзыва
FR-48: Система должна уведомлять продавца при появлении нового отзыва на его товар через вкладку уведомлений в веб-сервисе 
FR-49: Система должна уведомлять покупателя при появлении ответа от продавца на его отзыв через вкладку уведомлений в веб-сервисе 
Работа с жалобами
FR-50: Пользователь должен иметь возможность подать жалобу на продавца, а также посмотреть список своих жалоб с их статусами и ответами администратора
FR-51: Система должна уведомлять администратора при появлении новой жалобы через вкладку уведомлений в веб-сервисе
FR-52: Система должна уведомлять покупателя при изменении статуса его жалобы через вкладку уведомлений в веб-сервисе
FR-53: Система должна предоставлять администратору возможность посмотреть список жалоб, а также фильтровать список по статусу и сортировать их по дате
FR-54: Администратор должен иметь возможность менять статусы жалобы с “Открыта” на “Отклонена”/”Закрыта”, а также добавлять комментарий о причине изменения статуса
FR-55: Система должна предлагать возможные переходы статуса жалобы в виде выпадающего списка, отображая лишь допустимые переходы. Система не должна предлагать в выпадающем списке статусы, в которые нельзя перейти из текущего статуса(например, “Закрыта” в “Открыта”)
FR-56: Система должна иметь возможность обрабатывать определенные виды жалоб через внедренную ИИ-модерацию, подставляя в комментарий автоматический ответ ИИ-модератора
### Работа с аналитикой продаж
FR-57: Система должна предоставлять продавцу возможность просмотреть раздел аналитики продаж с информацией о выручке за определенный период
FR-58: Система должна предоставлять продавцу возможность просмотреть раздел аналитики продаж с информацией о количестве заказов за определенный период
FR-59: Продавец должен иметь возможность отфильтровать данные, собранные аналитикой, по товарам, категориям, периоду
FR-60: Система должна предоставлять возможность выгрузки отчета с выбранными фильтрами в Excel/CSV
### Управление пользователями
FR-61: Система должна предоставлять администратору возможность поиска пользователя по ключевым словам в виде имени пользователя или его email
FR-62: Система должна позволять администратору фильтровать список пользователей по их роли
FR-63: Администратор должен иметь возможность изменить роль 1 или нескольких пользователей сразу
FR-64: Администратор должен иметь возможность удалить пользователя(без возможности удалить себя)
FR-65: Система должна предлагать возможные роли в виде выпадающего списка
FR-66: Система должна запрашивать подтверждение удаления пользователя или изменения роли, а также запрещать изменение собственной роли администратора на любую другую роль и удаление собственного аккаунта администратора
### Работа с рекомендациями
FR-67: Система должна предоставлять администратору возможность просмотра и редактирования настроек рекомендаций
FR-68: Система должна запрашивать подтверждение изменения настроек рекомендаций
### Работа с резервным копированием и восстановлением данных
FR-69: Системный администратор должен иметь возможность просмотра списка бэкапов, а также запуска создания, восстановления и удаления бэкапа
FR-70: Система должна автоматически создавать бэкап ежедневно в 3:00 по Москве и удалять самый старый бэкап при создании нового
FR-71: Система должна запрашивать у системного администратора подтверждение удаления или восстановления бэкапа
### Работа с аккаунтом
FR-72: Система должна предоставлять возможность авторизации и регистрации пользователя в веб-сервисе
FR-73: Система должна предлагать выбор типа пользователя(“Покупатель” или “Продавец”) при регистрации пользователя в веб-сервисе с заполнением всех обязательных данных для роли пользователя
FR-74: Авторизованный пользователь должен иметь возможность редактирования данных профиля 
FR-75: Система должна проверять корректность заполненных полей и заполнение обязательных полей при регистрации, авторизации и изменении данных профиля 

## Нефункциональные требования
### Производительность (Performance)
PER-01: Время реакции системы на действие пользователя при редактировании данных(сохранение или редактирование карточки товара, обновление данных аккаунта, отзыва) не должно превышать 1 секунду
PER-02: Система должна отображать списочные данные с фильтром за 2 секунды или менее
PER-03: Система должна начать выгружать документы-отчеты за 7 секунд или меньше после запуска загрузки
PER-04: Время ответа системы при запросе страницы списка с максимальным размером пагинации (30 элементов) не должно превышать 500 мс
### Масштабируемость (Scalability)
SCA-01: Профиль нагрузки по ролям пользователей
1. Покупатель(примерно до 83% всех пользователей):
- скроллинг каталога(примерно 15 запросов по API поиска или фильтрации в минуту)
- оформление 15-20 заказов в месяц
- написание 15-20 отзывов в месяц
- тяжелые операции: выбор нескольких фильтров в каталоге, подгрузка фото или видео в отзыв
2. Продавец(примерно до 14% всех пользователей):
- загрузка тяжелых медиафайлов
- добавление и редактирование товаров
- обработка заказов
3. Админ/Сис.админ (до 3% всех пользователей):
- модерация жалоб и возвратов
- настройка рекомендаций
- контроль бэкапов
SCA-02: На момент запуска ожидается 100 активных пользователей
SCA-03: Через год ожидается рост до 1000 активных пользователей
SCA-04: Через 3 года ожидается рост до 10 000 активных пользователей
SCA-05: Через 5 лет ожидается рост до 20 000 активных пользователей
### Доступность (Availability)
AVA-01: Допустимый процент отказа или обслуживания системы составляет 99.9%
AVA-02: Окно обслуживания (без нагрузки от пользователей): с 02:00 до 03:30
AVA-03: Обязательное оповещение пользователей за 24 часа до плановых технических работ
### Безопасность и аудит (Security)
SEC-01: Система должна соответствовать требованиям информационной безопасности и Федеральному закону № 152-ФЗ “О персональных данных”(уровень защищенности УЗ-2)
SEC-02: Доступ к интернету из контура приложения строго ограничен (доступ к внешним API платежных шлюзов и служб доставки только через белый список IP-адресов)
SEC-03: Требуется ведение неизменяемого аудита действий пользователей для всех финансовых транзакций, смены статусов заказов, обработки возвратов и жалоб с хранением логов не менее 3 лет
### Надежность (Durability, Disaster Recovery)
DUR-01: Автоматическое полное резервное копирование данных системы ежедневно в 3:00 по МСК(совпадает с окном обслуживания)
DUR-02: Полуавтоматическое восстановление после сбоя работы системы
DUR-03: Пароли хранятся в зашифрованном виде
### Мониторинг (Monitoring)
MON-01: Использование современного стека мониторинга и алертинга на базе Prometheus, Grafana для сбора системных и бизнес-метрик
### Организационные и юридические вопросы (Legal, Regulatory and Compliance)
LRC-01: Соблюдение законодательства РФ:
54-ФЗ “О применении контрольно-кассовой техники”(правила выдачи кассовых чеков)
152-ФЗ “О персональных данных” (242-ФЗ локализация, уведомление Роскомнадзора об утечках данных и прочее)
289-ФЗ “О платформенной экономике”(четко разграничивает роли “Оператора цифровой платформы” (маркетплейс) и “Продавца”)
### Локализация и интернационализация (I18n, L10n)
L10N-01: На момент запуска поддерживается только русский язык с проектированием архитектуры приложения для последующего добавления других языков
### Целевые платформа и устройства пользователей
PLT-01: Поддержка последних двух стабильных версий веб-браузеров Google Chrome, Yandex Browser, Safari, Mozilla Firefox, включая мобильные версии
## Ограничения
LIM-01: Поддержка только русского языка
LIM-02: Поддержка работы маркетплейса и доставки только в пределах территории РФ
LIM-03: Проводить финансовые расчеты с продавцами и покупателями только в национальной валюте(рубли) через поддерживаемые платежные сервисы(PSP) 
LIM-04: Ответственность за физическую сборку, упаковку и логистику (отправку через Почту России или СДЭК) полностью лежит на продавце 
LIM-05: Возврат денежных средств покупателю осуществляется исключительно в полном объеме без поддержки частичных возвратов 
LIM-06: Удержание выплат продавцам на фиксированный период (7 дней) после доставки для обеспечения окна возврата  
LIM-07: Принятие на платформу только юридических лиц, ИП и самозанятых с официальным подтверждением прав на бренды одежды
LIM-08: Каждый цвет одного вида одежды оформляется строго отдельной карточкой товара (без возможности переключения цвета внутри одной карточки) 
LIM-09: Размер фото или видео, загружаемого в веб-сервис, не должен превышать 5Мб
LIM-10: Количество фото для одного товара не должно превышать 4
LIM-11: Количество видео для одного товара не должно превышать 1
LIM-12: Система поддерживает работу с файлами SKU лишь формата csv & xlsx
LIM-13: Размер файла, загружаемого в веб-сервис, не должен превышать 10Мб
## Принципы
